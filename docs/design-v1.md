# 个人工作生活 App v1 页面结构与交互设计文档

> 版本：v1（仅设计，不含代码）
> 使用者：仅本人，本机浏览器使用
> 数据形态：本机固定数据文件，Python 本地小服务读写

---

## 0. 文档说明

本文档描述第一版的页面结构、每个模块的功能与交互、数据模型草案和全局规则。目的是在动手写代码之前，把"长什么样、点了之后发生什么、数据存什么"全部定下来，可逐条批注修改。文中所有规则均为设计约定，实现时以此为准。

## 1. 全局信息架构

### 1.1 导航组织：九个模块怎么排

九个模块放在左侧竖排导航（宽屏）/ 底部或抽屉导航（窗口很窄时）。不按字母排，而按"一天里的使用顺序 + 工作/生活分区"组织，分三组：

| 分组 | 模块 | 顺序理由 |
|---|---|---|
| 总览 | 1. 首页、2. 今日计划 | 每天打开第一眼看到的两个页面，放在一起，构成"看今天"的入口 |
| 工作 | 3. 自媒体、4. 开发工作、5. 咨询工作 | 三类产出型工作，按"内容产出 → 项目推进 → 对人服务"排 |
| 生活 | 6. 健身计划、7. 饮食计划、8. 游戏娱乐 | 身体管理在前，娱乐在最后，形成"先自律后放松"的暗示 |
| 系统 | 9. 数据与设置 | 固定在导航最底部，与日常模块隔开 |

导航上每个模块只显示图标 + 名称，不显示角标数字（第一版不做未读计数，避免噪音）。当前所在模块高亮。

### 1.2 页面层级

全 App 统一只有两层页面 + 一层编辑态，不做三级跳转：

- **列表页（一层）**：模块主页面，展示该模块的核心列表或看板。九个导航项各对应一个列表页。
- **详情态（二层）**：点击列表中的一条进入。第一版详情不单独开路由页面，统一用**侧滑面板**从右侧滑出（宽度约屏幕 40%），列表仍在背景中可见，点遮罩或关闭按钮返回。例外：自媒体的"写稿"是长文本场景，用**全屏编辑页**（详见 4.3）。
- **编辑态**：与详情态复用同一个侧滑面板，进入编辑模式后字段变为可编辑。新建与编辑共用同一套表单，新建时表单为空。

层级规则：侧滑面板里不允许再打开第二个侧滑面板；面板内需要跳转其他模块时（如从咨询记录跳到首页）直接整页跳转。

### 1.3 全局通用控件

| 控件 | 统一行为 |
|---|---|
| 新建按钮 | 每个列表页右上角固定一个"+ 新建"主按钮，文案带对象名（如"+ 新建选题"）。键盘快捷键 `N`。 |
| 编辑入口 | 详情面板右上角"编辑"按钮；列表行悬停时出现铅笔图标，点击直接进入编辑态。 |
| 删除 | 任何删除都弹确认框，写明要删的是什么（如"删除选题《xxx》？其下稿件会一并删除"）。**删除后 5 秒内页面底部出现撤销条**，点撤销即恢复；5 秒后真正落盘删除。 |
| 搜索/筛选 | 列表页顶部一条工具栏：左侧搜索框（对标题/名称模糊匹配，输入即过滤，无回车），右侧筛选项（每个模块不同，见各模块小节）。没有搜索结果的模块（如首页）不放搜索框。 |
| 空状态 | 每个列表为空时显示一句话 + 一个新建按钮，如"还没有选题，把第一个想法记下来吧"。不放插画。 |
| 错误提示 | 保存失败（如文件写入异常）时页面顶部出现红色横幅"保存失败，请重试或检查数据文件"，操作不丢失，表单内容保留，可重试。 |
| 加载态 | 本地服务读写很快，不做骨架屏；超过 1 秒才显示转圈。 |

## 2. 全局交互规则

### 2.1 新建/编辑/保存

- **形式**：新建与编辑统一用右侧侧滑面板（自媒体写稿除外，用全屏页）。不用行内编辑、不用居中弹窗做表单，保证所有模块手感一致。
- **保存**：以**自动保存**为主——字段失焦或选项变更后 300ms 内自动落盘，面板右上角显示"已保存 HH:MM"字样。长文本（稿件正文、随手记）停止输入 1 秒后自动保存。提供"关闭"按钮仅用于收起面板。导航底部另有常驻"立即保存"按钮：它只是把待保存改动立即落盘，不改变自动保存行为——有待保存改动时提示"已保存 HH:MM（自动保存仍然开启）"；无待保存改动时提示"没有待保存的修改；自动保存始终开启"；按钮旁常驻"自动保存已开启 · 上次保存 HH:MM"。
- **撤销**：只有删除有 5 秒撤销条；普通编辑不做多步撤销（输入框内浏览器自带 Ctrl+Z 可用）。
- **校验**：唯一的硬性校验是"标题/名称不能为空"，其余字段都允许为空，不挡用户。

### 2.2 时间与日期的处理口径

- **"今天"的边界**：以自然日为准，但凌晨 0 点到 4 点之间仍算"昨天"（照顾熬夜场景），凌晨 4 点翻篇。该时间点以后可在设置中调整（第一版只做 0 点 / 4 点两档）。
- **跨天事项**：不做过夜计时。任何事项只属于某一个"计划日期"，过了当天未完成就进入"未完成"状态，由日终顺延规则处理（见 3.2），不自动跨天。
- **补记昨天**：所有按天记录的数据（健身打卡、饮食、游戏时长、开发随手记）的日期字段都可手动改，默认填今天，允许改成过去任意一天。补记的数据照常参与汇总（如首页"今天练没练"只认当天的记录）。
- **时区**：只用本机时间，不涉及时区概念。

### 2.3 数据落文件的体验设计

- **启动**：双击启动脚本（如 `启动.bat`）→ 后台启动本地 Python 服务 → 自动打开浏览器到 `http://localhost:端口`。若端口被占用，终端窗口提示并自动换端口。启动脚本所在文件夹里有 `data/` 目录，数据文件固定为 `data/app-data.json`（单文件，便于"复制即备份"）。
- **首次使用**：检测到数据文件不存在时自动创建空文件，浏览器打开后显示一次性的欢迎引导（只在第一次出现）：三句话——"数据存在本机 data 文件夹里；关掉浏览器不影响；备份=复制 data 文件夹"，底部按钮"开始使用"。
- **备份入口**：备份/恢复/清空全部收在「数据与设置」模块（见 4.9），首页和导航不放备份入口，避免误触。
- **服务关闭**：浏览器标签页关闭不影响数据；服务窗口关闭即停止，下次双击脚本再启动。

## 3. 首页与今日计划（全局核心）

### 3.1 首页

**页面定位**：一眼看清今天，不做操作主战场；可操作的部分只有三处——勾选今日事项、快速备忘、速览卡上的快捷入口。

**区块布局**（从上到下）：

1. **今日事项区**（占首屏主要高度）
   - 数据来源：各模块中"计划日期 = 今天"或"标记为今天"的事项自动汇总 + 在今日计划页手动添加的临时事项。
   - 取数口径：各模块如何产生"今日事项"见各模块小节的"汇总触发条件"。
   - 展示：按时间段（早上/白天/晚上）分组，段内按优先级（高→普通）再按创建时间排列。每条显示：来源模块小标签（颜色区分）、标题、勾选框。
   - 交互：勾选即完成，条目以淡入淡出动画收起到"已完成"折叠区（页面底部，默认收起，可展开回看，当天内可取消勾选恢复）。**勾选只改状态不删除，不弹撤销条。**
   - 为空时：显示"今天还没有安排，去今日计划加一条，或从右边随手记转一条"。

2. **快速备忘区**（今日事项区右侧或下方，窄屏时在其下）
   - 一个常驻输入框 + 备忘列表（只显示最近 10 条，更多进"今日计划"页看）。
   - 交互：回车即存一条备忘（纯文本，带时间戳）；每条备忘上有两个按钮：**"转待办"**（一键变成今日计划里的一条临时事项，原备忘保留并标记"已转"）、删除（可撤销）。
   - 数据来源：备忘是独立实体，只属于首页/今日计划。

3. **模块速览区**（页面底部，卡片网格，每行 3 张、共 6 张，六个内容模块各占一张）

   **卡片统一结构**（每张卡分三层，从上到下）：
   - **卡头**：模块图标 + 模块名；右上角一个"›"箭头，点击 = 跳到该模块主页面。
   - **摘要区**：1~2 行该模块今天最关键的数字/状态（各模块内容见下表）。
   - **快捷入口区**：卡片底部 1~2 个动作按钮，点击直接跳到对应模块**并自动打开相应功能**（不止跳页，而是落到具体操作），实现"在首页就把事办了第一步"。

   **各卡片摘要内容与快捷入口**：

   | 卡片 | 摘要区显示（取数口径） | 快捷入口按钮（点击后的去向） |
   |---|---|---|
   | 自媒体 | 今天有无发布计划及状态（未发/已发）；无则"今天无发布计划" | 「记选题」→ 跳到自媒体并直接打开新建选题面板；有待发布条目时另显示「去发布」→ 跳到看板并打开该卡片详情 |
   | 开发工作 | 今天随手记已写/未写（取当天 DevLog 是否存在） | 「记一笔」→ 跳到开发模块当前项目并展开今天的日志输入框 |
   | 咨询工作 | 未来 3 天待跟进客户数 + 最近一个客户名；无则"暂无待跟进" | 「记一次咨询」→ 跳到咨询模块并打开最近客户面板的记录表单；有待跟进时另显示「去跟进」→ 直接打开到期客户面板 |
   | 健身计划 | 今天已练/未练 + 当天训练名称 | 「今天打卡」→ 跳到健身打卡页并按模板带出今天的记录表单；另显示「记体重」→ 跳到体重页签并聚焦输入框 |
   | 饮食计划 | 已记 N 餐 · 喝水 M/8 杯 | 「记一餐」→ 跳到饮食页今天日期并聚焦下一餐输入框；「喝水 +1」→ **不跳页**，直接在卡片上给今天喝水数加 1（首页唯一允许直接改数据的入口） |
   | 游戏娱乐 | 本周已玩 X 小时（周一到今天时长求和） | 「记时长」→ 跳到游戏模块并打开当前在玩游戏的时长打卡 |

   **通用规则**：
   - 摘要数字为 0 或无数据时照常显示卡片，摘要区显示各自的"空"文案（如上表），快捷入口始终可用——空状态正是快捷入口最有用的时候。
   - 卡片整体不响应点击（只有"›"箭头跳模块主页），避免误触；快捷入口按钮是明确的操作目标。
   - 快捷入口只放"高频、一步能到"的动作，每个模块最多 2 个，不把模块功能全搬上来。
   - 「喝水 +1」是唯一在首页直接写数据的入口：点一下杯数 +1，卡片数字即时刷新，无确认、可再点继续加；减杯只能去饮食模块操作（防止误点连减）。

### 3.2 今日计划

**页面定位**：今天这一天的完整清单，是首页"今日事项区"的全功能版。

**区块与布局**：
- 顶部：日期（今天，可左右箭头翻看昨天/明天，仅查看，历史日期只读）。
- 主体分三栏/三段：**早上、白天、晚上**。每段一个列表，每条 = 勾选框 + 标题 + 来源模块标签 + 优先级标记。
- 底部：已完成折叠区；"日终整理"按钮。

**关键交互流程**：

- **自动汇总**：任何模块产生"计划日期=今天"的事项时，自动出现在对应时间段（时间段由事项自带字段决定，默认"白天"）。在今日计划页勾选完成，会同步回源模块（如勾掉"发布选题 X"，自媒体里该条发布计划也标记完成）——**状态是同一数据源，不是复制**。
- **手动添加**：每段底部"+ 加一条"，行内输入回车即建（这是唯一允许行内创建的地方，因为临时事项足够简单：只有一个标题）。手动添加的事项来源标签为"临时"，可设时间段和优先级。
- **勾选完成**：同首页规则，收起到已完成区，可恢复。
- **日终顺延**：点"日终整理"按钮 → 弹确认框"还有 N 条未完成，顺延到明天？"→ 确认后所有未完成事项的计划日期改为明天（来源模块里的对应事项同步改日期）。顺延动作**可撤销**（5 秒撤销条）。不自动顺延，必须手动点，避免睡一觉起来清单自己变了。
- **删除**：临时事项可删除（可撤销）；来自模块的事项不能在今日计划页删除，只能去源模块处理（防止在首页误删了项目任务）。

## 4. 各模块详细设计

### 4.3 自媒体（模块 3）

**场景**：选题 → 写稿 → 排发布 → 发布后手动填数据，是一条流水线，用看板表达。

**页面布局**：
- 主体为**四列看板**：`选题池` → `写稿中` → `待发布` → `已发布`。每张卡片 = 一条内容。
- 卡片显示：标题、平台标签（可多选：如 B 站/公众号/小红书）、目标发布日期（仅"待发布"列必有）、已发布卡显示播放/点赞数字。
- 顶部工具栏：搜索框、平台筛选、新建选题按钮。
- 看板上方一个"列表/看板"切换，已发布条目多了以后可切到列表视图按时间倒序看。
- **"发布后视频数据"图表卡**（已发布列表视图顶部）：副标题"最近 N 条已发布 · 播放/点赞/评论来自手动回填"；内容为播放/点赞/评论三项合计数字 + 逐条内容的横向条形图（按发布日期排列）。两种空态：无任何已发布内容时显示"还没有已发布内容；发布并回填数据后，这里会显示表现。"；有已发布但均未回填数据时显示"已发布内容还没有回填播放/点赞/评论，打开详情补填后图表会自动更新。"

**字段**（内容卡片）：
| 字段 | 说明 |
|---|---|
| 标题 | 必填 |
| 平台 | 多选标签 |
| 状态 | 选题池/写稿中/待发布/已发布，拖动卡片即改状态 |
| 大纲/正文 | 长文本，写稿阶段用 |
| 目标发布日期 | 待发布状态必填 |
| 实际发布日期、发布链接 | 发布后填 |
| 播放/点赞/评论数 | 发布后手动填，可多次改，记录最后修改时间 |

**关键交互**：
- **流转**：卡片可拖拽换列，也可在详情面板里改状态。拖到"已发布"时弹出小表单要求填"实际发布日期（默认今天）+ 链接（可空）"，确认后才落入已发布列——**这是"发布"动作的确认点**。
- **写稿**：卡片在"写稿中"列时，双击卡片或点详情面板里"开始写稿"进入**全屏编辑页**（左侧大纲、右侧正文，自动保存）。这是全局唯一不用侧滑面板的编辑场景。
- **汇总到首页的触发条件**：卡片的"目标发布日期 = 今天"且状态为"待发布"时，自动生成今日事项"发布：《标题》"，时间段默认白天；在首页/今日计划勾掉 = 该卡片提示"标记已发布？"引导用户补链接后转入已发布（若用户只勾选不补链接，卡片进入已发布但链接为空，允许）。
- **数据回填**：已发布卡片详情面板里有"数据"区块，播放/点赞/评论三个数字框，随时改随时存。
- **删除**：选题/写稿中删除直接可撤销删除；已发布的删除确认文案额外提示"发布数据将一并删除"。

### 4.4 开发工作（模块 4）

**场景**：以项目为单位推进，每天记"做了什么、卡在哪"。

**页面布局**：
- 左侧：**项目列表**（窄栏），每个项目显示名称 + 进度条（任务完成数/总数）。顶部"+ 新建项目"。
- 页头常驻"＋ 新增工作项"按钮：任何状态下都可直接新建工作项；当还没有任何项目时，通过该入口（或空态的快捷创建）会自动先建一个"我的工作"项目，新工作项归入其中。
- 右侧：选中项目后的**项目详情区**，分两个页签：`任务` 和 `开发日志`。

**任务页签**：
- 简单任务列表（不做看板）：勾选框 + 任务标题 + 截止日期（可空）。支持拖拽排序、按"未完成/已完成"分组，已完成默认折叠。
- 任务字段：标题（必填）、备注、截止日期、优先级（高/普通）、完成状态。
- **汇总到首页的触发条件**：任务"截止日期 = 今天"且未完成 → 生成今日事项"开发：项目名 - 任务名"。首页勾选完成同步任务完成。

**开发日志页签**：
- 按天倒序的日志流，每天一条：今天做了什么（文本）、卡点（文本，可空）。
- 当天日志不存在时显示一个"记一笔今天"的输入框，回车即建当天日志；已有则直接行内展示可点进去编辑（日志用行内展开编辑，不走侧滑面板，因为它就是一段话）。
- **首页摘要取数**：当天日志存在 = 摘要卡显示"已记录"。
- 项目字段：名称（必填）、简介、状态（进行中/已搁置/已完结）。已完结项目默认收起到列表底部。

**删除**：删项目需确认并提示"其下任务与日志一并删除"，可 5 秒撤销。

### 4.5 咨询工作（模块 5）

**场景**：围绕"人"——每个客户一张卡，每次咨询一条记录，到期待跟进的浮出来。

**页面布局**：
- 主体为**客户卡片网格**（或列表，可切换）。每张卡：客户名称、要做什么（一句话需求）、下次跟进日期（到期/临近时卡片高亮橙色边框）、最近一次咨询日期。
- 顶部：搜索框（按客户名/需求关键词）、筛选（全部/待跟进/已成交/暂停）、新建客户。

**客户详情**（侧滑面板，宽度用较大的 50%，因为这是高频阅读区）：
- 上部：客户基本信息（名称、联系方式、来源、需求描述、状态：跟进中/已成交/暂停）。
- 下部：**咨询记录时间线**，按时间倒序，每条记录：日期时间、议题、结论、下一步行动、下次跟进日期（可空）。
- 时间线顶部固定"记一次咨询"按钮，点了在面板内展开表单（新记录插到最上），不另开面板。

**关键交互**：
- **下次跟进日期**是核心字段：填了它，到期前 3 天起该客户进入首页摘要"待跟进"；**到期当天**，自动生成今日事项"跟进客户：某某"（时间段默认白天）。首页勾选完成 = 在客户面板里记为"已跟进"，但**勾选只是清掉提醒，客户仍需补一条咨询记录才算闭环**（摘要卡里客户数相应减少）。
- 删除客户：客户卡片、列表行与详情面板底部均有删除入口（卡片与列表行上的删除按钮不会误触进入详情）；确认框写明"N 条咨询记录一并删除"，确认后 5 秒内可撤销，超时未撤销则级联删除该客户及其全部咨询记录。

### 4.6 健身计划（模块 6）

**场景**：先有每周训练模板，每天照着打卡，记体重看曲线。

**页面布局**，四个页签：`日历`（默认）、`本周计划`、`打卡记录`、`体重`。

**日历页签**（默认）：
- 月历视图（周一开头、6 行格），头部可"‹ 上一月 / 回到本月 / 下一月 ›"翻月。
- 每个日期格子显示当天打卡摘要：训练名称（部位，如"胸+三头"）、逐动作明细——次数类动作显示"动作名 · 3 组 × 10/10/8 次"，时长类动作显示"动作名 · 30 分钟"；当天仅有计划未打卡时显示"计划 · 训练名"。
- 点任意日期格子打开该天的打卡编辑，可补记/修改（不限于今天）。

**本周计划页签**：
- 一周七天的表格，每格 = 当天训练安排（如"胸+三头""休息"）。这就是模板，**改模板只影响今天及以后，不回改历史打卡**。
- 每天格子里可填：训练名称 + 计划动作列表（动作名、组数×次数或时长）。设"休息日"标记。

**打卡记录页签**：
- 按天倒序的打卡列表。点"今天打卡"时，**自动把本周模板里今天的内容带出来作为初始记录**，然后按实际修改：每个动作记实际组数、重量（kg）或时长（分钟），可临时加动作、可标"没练"。
- 打卡保存后当天标记"已练"。一天可补记/修改，日期可改（补昨天）。
- **汇总到首页**：当天打卡记录存在且未标"没练" = 摘要卡"已练"。

**体重页签**：
- 上方一个输入框记今天体重（一天多次取最后一次），下方一条**简单折线图**（最近 30 天，无复杂统计），下方列表可改历史数据。

**删除**：删除某天打卡/体重记录可撤销。模板格子清空不算删除，不弹确认。

### 4.7 饮食计划（模块 7）

**场景**：快速记"吃了什么"，常喝水的打点，模板一键填。

**页面布局**：单页按天展示。
- 顶部日期切换（默认今天，可补记）。
- 页头下方为**月度日历总览**（周一开头、可翻月）：每个日期格子显示当天各餐条数（如"早餐 1 · 午餐 2"）与"喝水 M/目标 杯"；点任意日期格子，下方四餐与喝水区即切换到该天。
- 当天分五个区块：**早餐、午餐、晚餐、加餐、喝水**。
- 每个餐区块：已记内容列表 + 一个输入框（回车即加一条，如"鸡胸 150g + 米饭"）+ "从模板填入"按钮。
- 喝水区：一排杯子图标（默认 8 杯目标），点一下满一格，再点取消，纯打点。

**餐食模板**：
- 任何一条已记餐食可"存为模板"（起个名字，如"减脂午餐A"）。"从模板填入"弹出模板列表，点一下整套填入当前餐区。
- 模板管理（改名、删除）收在页面右上角"模板管理"入口里，删除可撤销。

**汇总到首页**：摘要卡显示"已记 N 餐 · 喝水 M/8 杯"。饮食不产生今日事项（不需要"提醒吃饭"）。

### 4.8 游戏娱乐（模块 8)

**场景**：游戏分状态管理，记时长和进度，娱乐量上首页。

**页面布局**：
- 顶部三个状态页签：**在玩 / 想玩 / 已通关**。
- 每个页签是游戏卡片列表：游戏名、封面（可无，用文字首字代替）、累计时长、进度备注（如"第三章"）、在玩卡片显示"本周时长"。

**字段**：游戏名（必填）、状态、累计时长（分钟，自动累加）、进度备注、通关日期（已通关时填）、一句话评价（已通关时可填）。

**关键交互**：
- **记时长**：在玩卡片上有"打卡"按钮，点开输入"今天玩了多久（分钟）"，默认记在今天，可改日期补记。时长明细按天存，累计值自动加总。
- **状态流转**：卡片详情里改状态（想玩→在玩→已通关）。转"已通关"时引导填通关日期（默认今天）与评价（可空）。
- **汇总到首页**：本周（周一到今天）所有游戏的时长明细求和 = 摘要卡"本周已玩 X 小时"。
- 删除游戏：确认 + 可撤销，时长明细一并删除。

### 4.9 数据与设置（模块 9）

**页面布局**：单页分四组，每组一个卡片式区块。

1. **备份与恢复**
   - 「导出备份」：点击把当前数据文件复制为带时间戳的备份文件（`data/backup-YYYYMMDD-HHmm.json`），并弹出该文件所在位置提示。按钮文案："导出备份（生成一个带日期的数据文件副本）"。
   - 「从备份恢复」：点击弹出文件选择（列出 data 目录下所有备份文件，按时间倒序），选中后**强确认弹窗**："恢复将覆盖当前全部数据，且不可撤销。当前数据会先自动导出一份应急备份。确认恢复？"→ 确认后系统自动先导出一份 `backup-before-restore-*.json`，再执行覆盖，然后提示"恢复完成，请刷新页面"。
   - 「清空数据」：红色按钮，强确认弹窗（需手动输入"清空"二字）："清空后所有模块数据归零，清空前会自动导出一份备份。"→ 自动备份后清空，回到首次使用的欢迎引导。
2. **外观**：深色/浅色切换（默认浅色），即时生效。只有这两档，不做主题定制。
3. **模块显示开关**：九个模块中除"首页""数据与设置"外，其余七个可隐藏（导航里不显示，数据保留，已隐藏模块的今日事项不再汇总到首页，并有一句提示"隐藏期间数据仍在，重新开启即恢复"）。
4. **偏好**：一天翻篇时间（0 点/4 点）、每天喝水目标杯数（默认 8）。

## 5. 数据模型草案

单文件 JSON 存储，顶层按模块分键。以下只列实体与关键字段，字段类型从简描述（实现时可细化）。所有实体都有：`id`（唯一）、`createdAt`、`updatedAt`。

### 5.1 今日计划 / 首页
- **TodoItem（今日事项）**：title、source（manual=临时 / selfmedia / dev / consult / fitness）、sourceId（来源实体 id，临时事项为空）、planDate（计划日期）、timeSlot（morning/afternoon/evening）、priority（high/normal）、done、doneAt。
  - 关系：sourceId 指向各模块实体；模块实体被删除时对应 TodoItem 一并删除。
- **Memo（快速备忘）**：text、convertedToTodo（是否已转待办）、todoId。

### 5.2 自媒体
- **ContentItem**：title、platforms[]、status（idea/writing/scheduled/published）、outline、body、scheduledDate、publishedDate、link、metrics{views, likes, comments, metricsUpdatedAt}。
  - 关系：scheduledDate=今天且 status=scheduled → 生成 TodoItem(source=selfmedia)。

### 5.3 开发工作
- **DevProject**：name、intro、status（active/paused/done）。
- **DevTask**：projectId、title、note、dueDate、priority、done。
  - 关系：dueDate=今天且未完成 → TodoItem(source=dev)。projectId 指向 DevProject，删项目级联删任务。
- **DevLog**：projectId、date、content、blocker。每天每项目至多一条（projectId+date 唯一）。

### 5.4 咨询工作
- **Client**：name、contact、source、requirement、status（following/deal/paused）、nextFollowupDate。
- **ConsultSession**：clientId、datetime、topic、conclusion、nextStep、nextFollowupDate。
  - 关系：clientId 指向 Client，删客户级联删记录；最新一条记录的 nextFollowupDate 同步为 Client.nextFollowupDate；到期前 3 天进首页摘要，到期当天生成 TodoItem(source=consult)。

### 5.5 健身
- **WorkoutTemplate**：dayOfWeek（1-7）、title、isRestDay、exercises[{name, sets, reps 或 duration}]。（固定 7 条）
- **WorkoutLog**：date、title、skipped（没练标记）、exercises[{name, sets[{weight, reps}] 或 durationMinutes}]。
- **WeightEntry**：date、weight。（每天一条，多次取最后）

### 5.6 饮食
- **MealLog**：date、mealType（breakfast/lunch/dinner/snack）、items[文本数组]。
- **MealTemplate**：name、items[文本数组]。
- **WaterLog**：date、cups（整数）。

### 5.7 游戏娱乐
- **Game**：name、status（playing/wishlist/finished）、progress、finishedDate、review。
- **GameSession**：gameId、date、minutes。
  - 关系：gameId 指向 Game，删游戏级联删时长；累计时长 = 该游戏所有 GameSession.minutes 求和（冗余存一份在 Game.totalMinutes 便于显示）。

### 5.8 设置
- **Settings**：theme（light/dark）、dayRolloverHour（0/4）、waterGoal、hiddenModules[]。
- 备份文件与主数据文件同结构，仅文件名不同。

## 6. 第一版不做的边界

明确排除，后续不因此返工：

1. 不做登录、账号、权限；不联网、不云同步、不做手机端适配（窄屏仅保证能用，不做专门设计）、不部署。
2. 不接数据库，全部数据 = 本机单个 JSON 文件 + 备份副本。
3. 不自动抓取任何平台数据：自媒体的播放/点赞、游戏的时长全部手动填。
4. 不做复杂统计报表：图表仅限两处——健身模块的 30 天体重折线、自媒体模块的"发布后视频数据"图表；其余只有计数与求和数字。
5. 不做系统通知/推送/开机自启；提醒只靠"打开 App 时首页能看到"。
6. 不做多语言；不做深浅色之外的主题定制。
7. 不做撤销栈/历史版本，仅删除有 5 秒撤销。
8. 不做标签体系、不做全局搜索（只有各模块内的标题搜索）。
9. 不做内容的富文本/图片附件：稿件、日志、备忘都是纯文本。
10. 不做数据的导入其他格式（如 Excel/CSV 导入）、不做甘特图；日历视图仅限健身/饮食模块内的月历，不做全局日历。
